## 已采纳方案

### 按用途配置

在设置页新增“提示词”入口，打开专用编辑页，提供“X 翻译”和“表达解释”两个选项。每个用途全局一份配置，切换供应商或模型仍使用同一份；解释调用继续沿用现有选模规则。

第一版不增加每模型覆盖、多套预设或模板变量语言，减少优先级和行为差异。连接测试保持程序内固定。

### 编辑与应用协议分开

可编辑正文描述角色、表达风格、语境判断和讲解要求。原有批准内容作为内置默认，首次迁移只做抽取和拼装，最终发送的完整默认系统提示词应与当前文本逐字一致，包括换行、空行和固定输出约定。

翻译的“输出格式”及追加的应用约定保持只读；解释的材料边界、JSON 字段和输出格式保持只读。原帖与输入材料的组装、纯文字范围、澄清处理、流结束检查和回填保护继续由程序管理。编辑器提供可展开的“应用固定规则”及“最终提示词预览”，明确实际发送的内容。

固定规则由程序统一拼装；它不能保证模型一定遵守语义要求，现有输出校验也不能识别所有无前缀澄清。因此需验证正常、澄清和异常输出，不能把保存成功视为模型质量验收。

### 提示词模块职责

2026-09-26：用户询问配置化时是否应把解释提示词抽出，随后同意开始实施。两类提示词一起整理，共用配置读取和拼装路径。

- 现有 `prompts.ts` 集中管理两类内置默认正文、固定应用协议和无数据库依赖的拼装函数，将解释系统提示词从 `ai.ts` 移入。后台最终提示词预览与实际调用复用同一拼装函数，防止展示内容与发送内容不同。
- 新增服务端 `prompt-settings.ts`，负责 SQLite 配置读写、版本校验与历史，并结合 `prompts.ts` 生成一次请求所需的生效提示词及版本快照。
- `ai.ts` 保留模型调用、流处理、输出校验和使用记录接入；取得生效提示词后传给模型，不维护翻译或解释的提示词正文。连接测试指令保持固定。

源码中的内置默认与固定协议随版本维护，后台编辑的自定义正文存入 SQLite。这样能集中检查默认内容、单独测试拼装和配置逻辑，并保留恢复默认的明确来源。

### 页面操作

- 显示当前使用“内置默认”还是“自定义”、当前版本、正文编辑框与字数。
- “保存并生效”是显式操作，未保存编辑不影响调用；离开页面时保护未保存内容。
- “恢复默认”先载入默认草稿，保存后才生效；历史版本同样先载入草稿，避免误点立即替换当前配置。
- 拒绝空白正文和超长文本，建议正文上限为 20,000 字符；保存冲突保留本地草稿并提示重新读取。

### 存储、生效与升级

SQLite 保存每个用途的当前配置及轻量版本历史；内置默认保留在代码。自定义保存为覆盖项，应用升级不覆盖用户正文；使用内置默认时跟随应用提供的默认内容。配置与历史纳入实例数据库备份，不把学习数据 JSON 导出描述为完整配置备份。

每次调用开始时读取并固定一次生效快照，同一份内容用于模型请求和使用记录。保存只影响后续请求，不改变正在流式输出的请求；改写作为新请求使用当时的当前配置。无需重启服务，扩展无需同步提示词正文。

保存使用版本号校验，并在一个事务中更新当前配置、增加历史版本；旧页面不得覆盖另一页面刚保存的内容。使用记录沿用现有用途字段，补充配置版本、默认正文版本和应用协议版本等可追溯标识，仍保留当次最终全文；旧记录不补造版本。

配置接口复用现有登录鉴权和同源写入保护。首版管理入口仅在网页展示，正常翻译与解释请求不增加客户端提交系统提示词的能力。

### 实施范围与验证

预计涉及共享类型和校验、数据库迁移、提示词配置服务与管理 API、模型调用接入、设置入口及编辑页、使用记录详情。遵循 Web 目录规则，实现时再查对应已安装框架文档；交付行为变更时新增 Changeset。

第一版交付编辑、最终提示词预览、保存生效、默认恢复、历史回退和使用记录追溯。草稿试跑及当前版对照可后续增加：试跑应复用同一套组装与解析、明确由用户点击发起真实模型调用、单独标识使用记录，且不保存草稿为生效配置。

实施验收至少覆盖：

- 默认提示词逐字一致；未配置实例升级后保持现有行为；自定义内容在重启与升级后保留。
- 保存、恢复和回退生效；空白、超长、未登录请求与版本冲突被拒绝。
- 请求中途修改配置时，正在执行的请求与对应日志保持原快照，下一请求使用新配置。
- 翻译正常输出、必要澄清、空输出、截断及取消；解释合法与非法 JSON；连接测试不受配置影响。
- 旧使用记录仍可查看；新增记录保存实际最终提示词与对应版本；日志失败不影响成功调用。
- 编辑页在桌面与 390px 布局可用，未保存与错误状态清晰；临时实例及本地协议模拟器验证调用链，真实翻译质量另用真实语境验收。
