### CI 复用现有验证

现有根 [package.json](../../package.json)提供 `pnpm typecheck`、`pnpm test`、`pnpm build` 和 `pnpm test:smoke`。CI 调用同一套命令，后续添加到现有测试集合的用例也随之运行，无需维护第二套业务测试。

干净环境需固定 Node 与 pnpm、使用锁文件安装、生成 Next.js 路由类型。HTTP 联调还需编排模拟模型服务、临时数据库、隔离应用实例、就绪等待和进程清理，见[验证说明](../testing.md)。补充 Docker 构建、实际启动及升级验证后，才能覆盖部署产物。现有单元测试不能替代真实 X 扩展、iPhone/PWA 或模型质量验收。

### GitHub 与发布建议

1. 整理首个提交，检查公开内容与忽略规则，确定仓库公开性及许可证。
2. 接入 PR/main 的 CI，汇总固定必需检查，并设置主分支保护。
3. 引入 Changesets 版本 PR；普通功能 PR 合并不发布，合并版本 PR 才发布。
4. 建议服务端与 Chrome 扩展独立版本；服务端发布镜像，扩展发布 ZIP 与校验文件，共享接口变化时联动处理兼容性。
5. 新增 Sayseed ACR 仓库和最小权限凭据；新装、升级验证通过后再推进 `stable`，服务器按 digest 部署。GitHub 无需持有服务器 SSH 私钥。
6. 首次部署及回滚验证通过后再接入服务器定时更新。

仓库公开性、许可证、外部 HTTPS 访问地址等仍需在实施时确定。扩展 ZIP 供解压加载，不意味着开发者模式扩展能自动更新。

### 部署适配边界

- 当前 [Compose](../../compose.yaml)使用本机构建与 Docker 命名卷，生产需新增拉取镜像的配置，固定项目及数据卷身份。
- Memos 更新器绑定了专属接口、数据库表和数据目录，不能仅重命名后使用；其目录归档不会自动包含 Sayseed 命名卷。
- 备份及失败恢复必须覆盖 SQLite、WAL、持久加密密钥与部署配置，不能只恢复镜像或网页 JSON 导出。
- 当前健康接口只返回成功，需要补运行版本识别和数据库可用性验证。
- 当前前端依赖根路径 API、跳转和 PWA 地址，不能只增加一个反向代理子路径即完成部署；外部入口与流式响应代理配置需一起验证。
- 真实服务器连接信息、权限配置和备份路径继续留在私有运维目录。
